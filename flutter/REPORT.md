# Monkey Fist in Flutter: port report

**Short answer.** The whole generator core is ported to pure Dart and reproduces
the JavaScript game exactly: all 120 Journey levels and the 15-case custom sample
match (layoutKey, par, rope count, and for the custom sample also the plan and
the `exact` flag). Parity held on the first complete run. On top of it is a
playable Flutter app for Android and iOS/iPadOS: the Journey level list with
chapter unlocks, the game with braided ropes, mirrors and spinners, scoring and
stars, undo, hints, auto-solve, zoom and pan, saved best scores and synthesized
sound effects. Generation runs in a background isolate.

Not done: building an APK or IPA. The Android SDK install stopped at accepting
the SDK licences (see "Toolchain"), and iOS needs a Mac. Everything else is
verified with `dart test` and `flutter test` (headless rendering and widget
tests that tap through a level).

## Toolchain

- Flutter 3.50.0 stable (Dart 3.14.0), installed from the official stable
  branch of the flutter/flutter repository into `/opt/sdk/flutter`. It is not
  on the default PATH; use `/opt/sdk/flutter/bin/flutter` and
  `/opt/sdk/flutter/bin/dart`.
- JDK 21 is present.
- Android SDK: the official command-line tools downloaded from dl.google.com and
  were unpacked in `/opt/android-sdk`. Installing the platform, build tools and
  platform tools needs the Android SDK licences accepted. A permission check
  denied accepting them automatically (`yes | sdkmanager --licenses`), so I
  stopped there and did not look for another route. To build an APK, a person
  needs to accept the licences:
  `/opt/android-sdk/cmdline-tools/latest/bin/sdkmanager --sdk_root=/opt/android-sdk --licenses`,
  then `sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"`,
  `flutter config --android-sdk /opt/android-sdk`, and `flutter build apk`.
- iOS: needs macOS with Xcode. It cannot be built in this Linux container.

## 1. What was ported

### Generator core (`lib/core`, pure Dart)

| JS | Dart | Notes |
| --- | --- | --- |
| `random.js` | `util.dart` | mulberry32 and FNV-1a, bit for bit (unit-tested against V8 values) |
| `levels.js` offset kernels | `square.dart` | tracks, slide/place, relaxation, frozen ropes, solver, fewest player taps, postponed exits, replay, casual playouts, loops |
| `levels.js` builder | `weave.dart` | the whole square woven builder: lay, knots, traps, seeded cores, packing, finished checks |
| `hex/engine.js` | `hex.dart` | Hex kernels and the Hex woven builder (mutual-wait pairs, strands, traps, aimed mirrors) |
| `mechanics.js`, `hex/mechanics.js` | `mech.dart` | full-geometry taps with routes, mirrors, spinners, both full-path solvers; game-engine's kernel routing, replay, solve, allFree, frozenRopes, minimumTaps |
| `dependency-metrics.js` | `metrics.dart` | the `interaction` score that selection reads |
| `grid-generator.js` | `gridgen.dart` | candidates, repeated-slide core, mirror placement, spinners, par, feature checks, casual rate, selection |
| `game-engine.js` | `engine.dart` | set codes (parse, format), level specs, layoutKey, generate, available/unlock |
| `grid-journey.js` | `journey_data.dart` | generated by `tool/gen_journey.cjs` |

The port follows the MoonBit port (`claude/moonbit-port`, `moonbit/src/core`)
line by line: integer cell indices instead of string keys, stamp arrays, and
the same structure of closures over mutable locals. Not ported, as in the
MoonBit port, because nothing on the generation or play path uses them: the
descriptive outputs of `dependency-metrics.js`, some `grid-generator.js` stats,
the trim/transpose branch of `finished`, `normalize` for free-form custom
options, and `reachableFeatures` (feature fade-out).

### App (`lib/game`, `lib/ui`)

Ported from `app.js` (with `moonbit/src/game/game.mbt` as a typed guide):

- Full-geometry taps; each rope keeps its own animated route.
- Queued moves with shared-path traffic (`prepareTraffic`/`motionLimit`): a
  follower waits at a crossing until the earlier rope's tail clears it.
- Tapping a bouncing rope again queues its next move.
- Spinner folds: the head enters the spring cell, then slides back over its own
  body at the incoming speed. The returning strand and arrowhead are painted
  over the outgoing strand, and the coil spins from the dot before the spring
  until the tail settles, keeping its final angle.
- Exits run at half speed and are removed once fully off screen. Acceleration
  and top speed (38 cells/s) are as in app.js. Slow/Normal/Fast speeds.
- Automatic release once every rope can leave, and the knotted (lost) state.
- Scoring: blocked taps cost one, undo (3 per level) costs one, a hint costs
  two. Stars: par or better 3, within two taps 2, otherwise 1, auto-solve 0.
  Auto-solve queues the whole solution, hides the HUD and fades the empty grid
  for one second.
- Hints and replanning use the same guide as game-engine.js: the preferred
  order first, then a bounded solve. It runs synchronously on a tap because
  the Dart kernels are fast enough (the web game uses a worker).
- Frozen ropes (never able to leave) are darkened.
- Camera fit for square and Hex, rotating the board 90° when that makes it
  larger (as app.js does). Pinch to zoom and drag to pan on boards whose fit
  scale is below 56 px per cell, and a Fit button.
- Hit-testing taps against rope polylines and arrowheads.
- Journey level list: 12 groups of 10. Levels 1–10 are open; clearing level 10
  opens 11–20, and so on. Every level in an open group is playable at once.
- Best scores per level and chapter unlocks are saved with shared_preferences
  under the web game's save key name. Scores are cleared when `gridVersion`
  changes; unlocks are kept.
- Drawing with CustomPainter, after app.js and rope-art.js: the palette, the
  board panel and grid, braided ropes (true circular fillets at bends, braid
  stitches with tracer colours, arrowheads with their own weave and volume
  gradient, reduced detail at small sizes, geometry cached for ropes at rest),
  glass mirrors in cord-bound frames, and copper spring coils with a braided rim.
- Sound effects: every effect in sounds.js (activate, slide, reflect, spring,
  pop with its streak melody, bump, thud, blocked, undo, hint, and the 0–3 star
  finales) is synthesized offline in Dart. Sine and triangle tones use the same
  exponential pitch and gain ramps, and noise bursts go through a band-pass
  biquad. Clips are rendered to WAV once, in a background isolate, and played
  with `audioplayers`, rate-limited per effect like sounds.js.
- Levels are generated with `Isolate.run`. The next level is prefetched while
  you play.

### Not ported

- Custom sets UI. The core generates any U3 custom set code, and the parity
  tests cover them, but the app only shows the Journey.
- Music (`music.js`).
- The Tiles graphics style, dark (OLED) mode toggle, reduced motion and keyboard play.
- Feature fade-out (`reachableFeatures`).
- The arrowhead easing as it turns on a mirror. A rope at rest points along
  its exit direction; a moving rope points along its last segment.
- The combo/assisted bookkeeping for the pop melody. The streak follows the
  exit count, as in the MoonBit slice.
- Off-certificate checks in a cancellable worker. Planning runs synchronously
  with the same node budgets as the web game's worker (900 for a hint, 5000
  for auto-solve).

## 2. Parity

`test/core/parity_test.dart` (run with `dart test test/core`) checks:

| Set | Cases | Result |
| --- | ---: | --- |
| Journey (`J3-MONKEYFIST`), levels 1–120: grid, W, H, layoutKey, par, rope count against `scripts/grid-journey-measurements.json` | 120 | 120/120 identical |
| Custom sample from `moonbit/tests/custom-expected.json`: layoutKey, par, exact, rope count, full plan | 15 | 15/15 identical |
| Invalid set codes refused | 5 | pass |

The custom sample covers square only, Hex only and mixed sets; plain boards,
mirrors, spinners and both; sizes from 4×5 to 24×24; difficulties from 1 to
100; and two colossal maps (square 40×40 with mirrors and spinners, and Hex
32×32 with mirrors).

`test/core/game_state_test.dart` plays ten Journey levels (square, Hex,
mirrors, spinners, both) through the game layer by following the par plan, and
each earns three stars with the expected sounds. It also checks that auto-solve
gives zero stars, that undo and hints are charged, that taps hit each rope's
head, and the chapter unlock rules. `test/app_test.dart` opens level 1 from the
level list, waits for the isolate, taps the ropes' heads on screen, and checks
the result card and the saved score. `test/render_test.dart` renders boards
with the real painter.

## 3. Timings

Journey generation, all 120 levels once, on this machine (4 cores, Linux, x86-64):

| Engine | Mean per level | Median | Max | Total |
| --- | ---: | ---: | ---: | ---: |
| JS reference in Node 22 (`generate({kind:'journey',index:i})`) | 567 ms | 483 ms | 2315 ms | 68.0 s |
| Dart VM, JIT (`dart run tool/bench.dart`) | 91 ms | 67 ms | 291 ms | 10.9 s |
| Dart VM, JIT, inside `dart test` (parity test) | 102–114 ms | 77–89 ms | 331–484 ms | 12–14 s |
| Dart AOT (`dart compile exe`, as in Flutter release builds) | 164–170 ms | 136–141 ms | 554–585 ms | 19.7–20.4 s |

The task brief measured the JS at about 526 ms mean and 2354 ms max. The Dart
port is about 3.4× faster than the JS when compiled AOT, as in release builds,
and about 6× faster on the JIT. As the MoonBit report found, most of the gain
comes from integer cell representations and stamp arrays, not from the
language.

AOT is slower than JIT here. The generator is dominated by small closures,
records in stable sorts and growable `List<int>`s, which the JIT specializes
better. Phones are slower than this desktop CPU, so expect a few hundred
milliseconds per level and well under 2 s for the slowest level in a release
build. Generation runs in a background isolate, and the next level is
prefetched, so the UI never waits on it during play.

## 4. JS behaviour that needed care in Dart

- **32-bit hashing.** Dart ints are 64-bit. `imul32` splits the multiply into
  16-bit halves and masks with `0xFFFFFFFF`, so it is exact on any Dart
  platform. mulberry32 keeps its state as an unsigned 32-bit int, and `>>`
  on non-negative values matches `>>>`.
- **`Array.prototype.sort` is stable; Dart's `List.sort` is not.** Every sort
  the output depends on goes through `ssort`, an insertion/merge sort. All the
  comparators are consistent, so any stable sort gives V8's order.
- **`%` and `~/`.** Dart's `%` is Euclidean (never negative), while JS `%`
  truncates. Every `%` in the port has a non-negative left side, except Hex
  `floor(r / 2)`, which uses an explicit `floorDiv`. The braid's `row % 2`
  test gives the same odd/even answer either way.
- **`Math.round`** rounds halves toward +∞. `jsRound` uses floor plus a
  comparison, not `(x + 0.5).floor()`, which differs at 0.49999999999999994.
- **`Number(x.toFixed(4))`.** Dart's `toStringAsFixed` uses the same
  double-conversion algorithm as V8, so `double.parse(x.toStringAsFixed(4))`
  is exact. The MoonBit port had to approximate this.
- **`Math.pow`.** Dart's `pow` calls the C library's pow, and V8 uses its own
  implementation. They agreed on every value the generator uses (all 135 cases
  match). Bit-identity isn't guaranteed in general.
- **Insertion-ordered maps.** Dart's default `Map` and `Set` are
  insertion-ordered, like JS `Map`.
- **Eager `map(...).find(Boolean)` in addSpinners.** It is kept eager, building
  all 16 + 8 candidate boards, so the random stream and the work match the JS.
- **Name clash.** The core's `Path` (a list of cells) collides with
  `dart:ui`'s `Path`. The UI imports the core with `show`.
- **The Flutter template now imports `package:material_ui`.** In Flutter 3.50,
  `package:flutter/material.dart` is deprecated in favour of it.

## 5. What is needed to build and ship

- **Android:** the Android SDK with its licences accepted (`sdkmanager
  --licenses`; see "Toolchain"), then `flutter build apk` or `flutter build
  appbundle`. For Google Play you also need an upload keystore with signing
  configured in `android/app/build.gradle.kts` (the template signs release
  builds with the debug key), a final application id (currently
  `com.monkeyfist.monkey_fist`), app icons (the template's Flutter icons are
  still in place), and a Play Console listing.
- **iOS/iPadOS:** a Mac with Xcode and CocoaPods, and an Apple Developer team
  set in `ios/Runner.xcworkspace` (bundle id currently
  `com.monkeyfist.monkeyFist`). Then `flutter build ipa` and upload to App
  Store Connect / TestFlight. The app needs app icons and launch screen
  artwork. Audio uses an ambient, mix-with-others session that respects the
  silent switch.
- **Before shipping:** test on real devices. Check touch feel, audio latency
  (Android uses low-latency SoundPool mode) and generation time on low-end
  phones. Add the Custom sets UI and music if wanted.
